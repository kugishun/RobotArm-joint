# IK制御と起動メニュー

2026-09-26。既存Aのマッピング式・倍率・関節参照を維持し、別コンポーネントとしてIKを追加。

## 起動と操作

1. `Assets/Scenes/SampleScene.unity` を開きPlay。
2. 起動メニューで `Original joint mapping (A)` または `Hand position / orientation IK (B)` を選ぶ。
3. mocopiから姿勢が反映されていることを確認し、手を操作開始位置に置いて `Calibrate / recenter`。
4. IKでは右手の移動を校正位置からの相対移動として反映する。初期倍率0.5、メニューで0.1〜1に変更可能。
5. `IK: follow hand orientation` を外すと、位置だけを入力し手先の向きは校正時の向きに固定する。
6. `Change control method` で選び直せる。切替後は再校正が必要。

メニューは既存のマッピングを持つシーンに実行時に自動追加する。Aも起動メニュー経由では手動校正になる。元の自動校正設定はシーン上では維持している。

## 座標と追従点

右手ボーンを入力とし、校正時のAnimatorのyawを除去してUnity世界座標へ対応させる。胴体に毎フレーム追従する座標系ではない。人の腕の長さをロボットと等しくする方式でもない。

`UpperArmRobotMapper` に追加した `HandPoseIkController` はEditモードで設定できる。既定の追従点はJ6リンクのTransform（フランジ側の基準点）。把持中心そのものではない。把持中心で追従させるには、J6配下の固定されたTransformを用意し `Tool Center Point` に設定する。動く指リンクを指定しない。工具オフセットの実測は未実施。

位置目標 = 校正時の工具位置 + 校正時の入力座標変換 × 手の移動 × 倍率。
姿勢目標 = 入力座標へ変換した手の相対回転 × 校正時の工具姿勢。

## 実装

- `ArmPoseSolver.cs`: 現在のArticulationのアンカーから仮想運動学を構成。減衰最小二乗法、関節制限、誤差を減らすステップ選択。実際のTransformを試行的に書き換えない。
- `HandPoseIkController.cs`: 位置・姿勢目標を生成し、最大45度/秒の指令変化でxDriveへ適用。姿勢誤差は位置と重み0.15で合わせる。全域の収束や到達可能性の証明はない。
- `RobotControlMenu.cs`: 起動選択、排他切替、再校正、倍率、位置のみ/位置姿勢の選択、実測手先誤差表示。選択待ちではUnityの現在関節角を保持する。
- URDF付属のキーボードController/JointControlは、同じ関節への書込み競合を避けるためこのメニューの実行中は無効化する。元のコンポーネントは削除しない。
- `MyCobotUdpJointSender` は選択した方式から指令を取得する。送信コンポーネントが別オブジェクトにあっても既存のjointSource参照で対応付ける。

## UDPと未実装事項

起動メニューのUDP出力は既定OFF。ONを選択した場合だけ、校正済みで適用済みの選択ソースを送る。既存の宛先・レート・ペイロード形式・gripper設定は維持。

入力Transformが有効でも受信停止で古い姿勢が残る場合は検出できない。受信タイムアウト、衝突回避、実機の停止応答は本変更で追加していない。メニューへ戻る操作は実機の非常停止命令ではない。新しいグリッパ開閉入力はまだ追加していない。

到達できない目標や特異姿勢では誤差が残る。画面の `Converging / target may be unreachable` は非収束の表示で、到達不能を厳密に判定するものではない。

## 目標マーカー入力（mocopi不要）

起動メニューの `IK test: target marker (no mocopi)` を選択する。現在の工具姿勢で自動校正し、シーン直下に `IK Target Marker` を生成する。マーカーはロボットの子にしない。

1. Playを継続した状態でGameビューの `Select target marker` を押す（またはHierarchyで同名オブジェクトを選択）。
2. Sceneビューを開き、必要に応じてFキーで選択対象へ移動する。GizmosをONにすると黄色の球と赤X・緑Y・青Zの軸が見える。
3. Wの移動ツールで少しずつ移動する。InspectorのTransform Positionから数値指定もできる。
4. Eの回転ツールで向きを変更する。起動時にfollow hand orientationをOFFにした場合、位置だけ追従し向きは開始時で固定される。
5. `Reset marker to current tool pose` で現在の実際の手先姿勢へマーカーを戻し再開する。

マーカーのワールド位置・姿勢をそのまま目標とするため、mocopi用の移動倍率・校正座標変換は適用しない。目標の先は同じIK、関節制限、速度制限、誤差表示を使用する。テストモードはUDP出力チェックに関係なく実機送信不可。メニューへ戻るとマーカーを非表示にし、別方式への切替では校正を無効化する。

このモードの操作はUnity EditorのSceneツールが前提。Playを止めると生成マーカーは消える。目標に届かない場合は誤差が残るので、近い位置へ戻して確認する。

追加検証：Animatorなしのマーカー入力、ワールド座標の一致、姿勢固定、無効マーカー、UDP遮断、入力切替後の校正無効化をEditor検証に追加。C#コンパイルと既存の静的監査は成功。今回のSceneビュー操作とEditor検証の実行は未確認。

### マーカー操作の補足と更新

W/Eは移動・回転ツールの選択であり、押すだけでは動かない。Sceneビューで矢印／回転リングをマウスでドラッグする。`Select target marker` はマーカー選択と移動ツールへの切替、既存Sceneビューへのフォーカス・フレーミングを行う。

GameビューにもX/Y/Zの±操作を追加した。移動は1クリック1cm、回転は世界軸回りに1クリック5度。表示されるTarget world positionの数値が変わるか確認できる。姿勢固定時は回転ボタンを無効化する。小さなGameビューではパネルをスクロールできる。Unity EditorのPauseを解除した状態で確認する。

ユーザーのログにより既存のIK幾何検証成功を確認済み。今回の操作UI修正は通常・UNITY_EDITOR定義の両方でコンパイル成功。実際のPlay追従は引き続き要確認。タスクUIではEditor実行環境と幾何検証を完了、位置追従を作業中とし、コマンド自動検証の再確認を別タスクにした。

マーカーの移動・回転操作にロボット手先が追従することをユーザーが確認。タスクUIの位置・姿勢の基本追従を完了とした。これは定性的なPlay確認であり、位置・姿勢誤差、収束時間、到達不能・特異姿勢からの復帰、mocopi入力経路、実機の検証完了を意味しない。追従精度の測定とmocopi入力での確認を独立した残タスクとして追加。

### IK校正姿勢と追従点の表示

ここでの校正はmocopi本体のキャリブレーションとは別。人の現在の右手位置・向きと、ロボットの現在の工具位置・向きを基準として対応づける。指定のTポーズや、ロボットと同じ関節姿勢は不要。

初回確認では、正面を向いて胴体を止め、肩を下げ、肘を軽く曲げて右手を体の前の楽な位置に置く。腕を伸ばし切らず、前後左右上下へ動かす余裕を残す。手首も無理のない角度で静止する。その状態で校正し、最初は数cm程度の移動から確認する。これは操作開始姿勢の提案であり、精度を保証する姿勢ではない。校正時の手の向きが現在の工具の向きへ対応し、その後の回転差が入力になる。校正はロボットを特定の開始姿勢へ移動させる機能ではない。

IKの `Show tracking points` をONにすると、Gameビューに水色ACTUAL（実際の工具点）、黄色TARGET（IK目標）、紫HAND INPUT（mocopiの右手ボーン位置）を表示。カメラはMainCameraタグのカメラを使用し、画角外や背面の点は表示しない。GameビューではGizmos不要。SceneビューではGizmosをONにすると点、姿勢軸（赤X・緑Y・青Z）、実点と目標を結ぶ線を表示。黄色は校正後に表示する。

標準の追従点はJ6フランジ。`Tool Center Point`を指定した場合はその点を表示・制御する。紫はアバターのRightHandボーンであり、指先や実測の手掌中心ではない。表示は制御と同じ点を可視化するもので、TCP位置を自動決定するものではない。

可視化のC#コンパイルは成功。実画面での見やすさは確認待ち。

### Aと共通の開始姿勢（最新仕様）

IK選択直後にAの `Robot Base Angles + Offset` を読み取り、Aのマッピング範囲とDrive範囲の共通範囲で制限した姿勢へ移動する。現在のSampleSceneは J1〜J6 = [0, 0, 0, 90, 90, 0] 度。J1のみ90度へ移動する案は取りやめた。Aの設定が変わればIKの開始姿勢にも反映される。

移動は各軸最大30度/秒（Start Speed Degreesで設定）。各関節の目標差1度未満、速度2度/秒未満の状態が0.5秒続くまで待つ。30秒以内に到着しなければ現在姿勢の保持指令へ切り替え、エラーと再試行ボタンを表示する。移動中・失敗時は校正を禁止する。方式選択へ戻ると開始移動を中断する。

mocopiモードは停止後に人が操作姿勢を取り、Calibrateを押す。テストモードは停止後にマーカーを生成・自動校正する。これにより旧手順の「選択直後にマーカー生成」は「開始姿勢到着後に生成」に変わる。追従開始後の再校正は従来どおり現在位置でのrecenterであり、開始姿勢へ戻したい場合は方式を選び直す。

共有するのはロボットの校正時関節姿勢。人体入力はAの特徴角差ではなく、IKの手先位置・回転差を維持する。開始移動はUnity内のみで、未校正のためUDPでは送らない。実機開始姿勢との同期は別途必要で、本変更では実機を動かしていない。

通常・Editor定義のコンパイル成功。A基準角とオフセット、制限の共通範囲を取得し、取得だけでは関節を動かさないことを検証するEditorテストを追加。今回の開始動作と追加テストのUnity実行は未確認。

### 校正ボタンが無効の場合

開始姿勢移動中と開始失敗時はCalibrateを無効にしている。停止条件は全6軸の誤差1度未満・速度2度/秒未満が0.5秒継続。今回、誤差最大の関節番号・最大速度・経過時間を表示し、時間切れでも診断値を残すようにした。基準姿勢へ到達できない具体的原因はまだ特定していない。

`Use current pose (cancel start move)` で開始移動を中止し、実測の現在関節角を保持するとCalibrateを使用できる。停止を確認して校正する。この操作はAの開始姿勢への到達を保証しない。Aの姿勢が必要な場合は表示された誤差・速度を確認して原因を解消する。無効なロボット構成ではこの復帰操作も拒否する。通常・Editor定義のコンパイル成功、Play再確認待ち。

## 3姿勢による人・ロボット操作範囲の同期（最新仕様）

mocopi IKの開始メニューで `Mocopi: calibrate human / robot movement ranges` をON（既定）にする。従来の単一倍率を使う場合はOFF。マーカーテストとAはこの範囲校正を使わない。

### 手順

1. Aの開始姿勢への移動が終わるのを待つ。基準となる楽な手の姿勢を取り `Capture neutral / restart range calibration` を押す。手・工具の基準位置と向きを記録する。
2. 右腕を上へ伸ばして静止し `1. Capture arm UP`。
3. 右腕を前へ伸ばして静止し `2. Capture arm FRONT`。
4. 右腕を右横へ伸ばして静止し `3. Capture arm RIGHT`。右手なので横方向は右を使う。
5. ロボット範囲の計算を待つ。計算中はロボットを試行的に動かさず、仮想運動学だけを使用する。
6. 最初の手の位置・向きに戻し、`Start tracking from neutral` を押す。基準から位置5cm以内・姿勢10度以内が必要。

身体の正面は校正時のAnimatorのyawから取得する。操作座標はX=右、Y=上、Z=前で、ロボット側のUnityワールドX/Y/Zに対応する。登録時は腰位置5cm・回転15度を越える胴体移動を拒否する。指定軸に5cm以上の伸びがなければ登録を拒否する。人体の最大可動をセンサが自動認定するわけではないため、各方向で利用したい最大位置を人が登録する。

### 範囲の意味と換算

基準姿勢と3姿勢から各軸の観測最小・最大を計算する。基準位置0を維持し、正負それぞれの観測範囲をロボット範囲へ区分線形変換する。例えば人の前方範囲0.40m、ロボット推定前方範囲0.20mなら、人が前方へ0.20m動くと目標は0.10m移動する。範囲を越えた入力は端で制限する。

ロボット側は現在の開始点から世界座標の±X/±Y/±Zへ、校正時の工具姿勢を固定して1cm刻みでIKを解く。関節制限内・位置誤差3mm以内・姿勢誤差2度以内で連続到達できた最後の点を採用する。各方向で最初の非収束時に探索を止める。現在のIK解の近傍での到達範囲推定であり、全解を調べた厳密な最大到達範囲ではない。いずれかの正方向が1cm未満なら校正完了とせず、開始姿勢の見直しを案内する。

3姿勢だけでは全方向の人体最大範囲は測れない。左・下・手前も3姿勢中に観測された幅だけを使い、5cm未満の負方向は未測定として0で制限する。未測定側を正方向の対称値で補わない。全方向の最大値を得るには左・下・手前の追加計測が必要。

軸ごとの最大値を組み合わせた箱の隅が到達できるとは限らず、工具姿勢が変わると到達範囲も変わる。範囲同期中は各フレームのIK結果も同じ精度条件で確認し、解が得られない目標では新しい関節指令を適用せず直前の指令を保持する。入力を到達可能な位置・向きへ戻すと再試行する。範囲推定も追従時の判定も衝突検査を含まない。

登録中・計算中は追従とUDP送信を開始しない。再校正・方式切替で測定結果を無効化する。工具点・姿勢追従設定・関節制限を変更した場合も再校正が必要。範囲はPlay中のメモリにのみ保持される。mocopi受信鮮度検出は引き続き別タスク。

### 表示・検証

操作パネルに人の観測範囲とロボットの推定範囲をm単位で表示。SceneビューのGizmosには工具基準点からの3本の到達軸を描く。到達範囲が直方体であると誤認しないよう箱は表示しない。

`Tools > Robot Arm > Validate Workspace Mapping` に範囲変換テストを追加（基準点、各軸の最大点、中間点、範囲外入力、未測定側、過小幅、切替による無効化）。既存のValidate IK Solverからも実行する。通常・UNITY_EDITOR定義のコンパイルに成功。今回追加したテストと3姿勢フローのUnity内実行は未確認。開いているEditorは中断していない。
