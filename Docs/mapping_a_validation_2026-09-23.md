# A方式の初回検証と修正記録

2026-09-23。対象：コミット `54812c4` の実装・SampleSceneから開始。

**判定：Aは研究用の基準方式として、まだ確定できない。**

入力特徴量を各軸へ個別対応させる方式として説明できるが、人体の6関節角を再現しているわけではない。今回はコードで判断できる不具合を修正した。動作の意味を変える対応式・倍率・反転・基準角は維持している。Bは追加していない。

**入力と対応の妥当性**

| 軸 | 現在の入力 | 説明できる操作意図／未解決事項 |
|---|---|---|
| J1 | world上の上腕yaw | 左右方向を旋回操作へ対応。胴体の回転も入力になる |
| J2 | world上の上腕pitch | 腕の上げ下げを関節操作へ対応。手先が上下だけに動く保証はない |
| J3 | 上腕yawに沿う垂直平面へ投影した符号付き肘角度 | 同じ平面内の屈曲を対応。真の3次元肘角度と異なり、平面外・投影退化の検証が必要 |
| J4 | 上腕yawに対する前腕yaw | 前腕方向で追加軸を操作。回内・回外ではなく、肘屈曲との干渉がある |
| J5/J6 | 前腕yawを除いた手のEuler X/Z | 手の姿勢で末端側の軸を操作。前腕pitch/rollが残り、純粋な手首角ではない |

操作意図は現状を整理したもので、過去にその理由で実装されたと断定するものではない。

**修正した項目**

1. 手動校正時に古い角度キャッシュを使用していた。現在のTransformを読み直して校正する。
2. 前腕が無効でも上腕だけ更新され得た。全姿勢の検査後に特徴量を更新し、ゼロ長・非有限値等の無効入力では駆動と送信を進めない。
3. 肘差分の単純引き算を `DeltaAngle` に変更。179°→−179°で−358°になる問題を2°に修正。ただし基準から±180°を越える動作全体の連続化ではない。
4. 固定Lerpを時間刻み対応に変更。`alpha = 1 - (1 - smoothing)^(60 * dt)` とし、旧60 Hzの応答を基準とする。60 Hz以外では旧実装の応答から変わる。
5. スクリプト範囲とDrive範囲の共通範囲で制限し、適用後の角度を外部取得値にも保存。Unityの指令角とUDP値の不一致を修正。
6. 度の指令を直動関節へ適用しないよう、RevoluteJointのみ許可。固定軸、不整合な範囲、非有限指令も適用しない。
7. UDPの条件に、校正済み、有効姿勢、全6軸へ適用成功、ソース有効を追加。起動直後・再校正直後も、関節反映が済むまで送信しない。
8. mocopiのUpdate後に読むためAをLateUpdateへ、送信を実行順100のLateUpdateへ変更。Project Settingsで順序を上書きする場合も入力→A→送信を維持する。

`CanSendJointTargets` は受信鮮度を保証しない。mocopiが途絶えても最後のTransformは幾何学的に有効なため、別途タイムアウトが必要。また送信停止は実機停止命令ではなく、実機側のキュー・停止処理は未確認。

**シーン設定の監査結果**

全6関節の参照先が存在し、シリアライズ上は回転関節である。

| 軸 | スクリプト範囲（度） | Drive範囲（度、概数） | 適用共通範囲（度） |
|---|---|---|---|
| J1 | −90〜90 | −167.88〜167.88 | −90〜90 |
| J2 | −130〜165 | −134.65〜134.65 | −130〜134.65 |
| J3 | −165〜165 | −144.96〜144.96 | −144.96〜144.96 |
| J4 | −100〜100 | −144.96〜144.96 | −100〜100 |
| J5 | −100〜100 | −167.88〜167.88 | −100〜100 |
| J6 | −100〜100 | −179.91〜179.91 | −100〜100 |

これはUnity設定の監査であり、実機の許容範囲を実測・認証したものではない。

J4/J5は基準角90°、上限100°で、正方向の余裕は10°しかない。J5は倍率0.5なので入力差分20°で上限へ達する。比較実験前に、作業領域と開始姿勢から基準角・倍率の決定手順を整理する必要がある。

**反例：J4は肘屈曲でも変わる**

上腕仰角45°を固定して、同じ垂直平面内で前腕を100°曲げると、前腕仰角は145°となる。水平投影が反転するので前腕yawは180°変わり、現在のJ4特徴も180°変わる。垂直付近でyawを保持しても、水平成分が再び十分大きくなった後の反転は防げない。

これは独立した肘・前腕操作を主張するうえで重要な反例である。平滑化を強めるだけでは解決しない。対応式を変更するか、操作可能な姿勢領域を限定して説明する必要がある。

**実施した検証と限界**

- Unity 6000.0.74f1実DLLを参照したC#コンパイル：変更2スクリプトとEditor検証スクリプトに成功。Inspectorで設定する参照のCS0649警告のみ。
- 独立した数式検算：0→80°ステップ、0.1秒後の値は30/60/120 Hzとも59.02848°。実機応答の測定ではない。
- 肘境界の独立検算：179°→−179°の差分2°。
- シーン参照・回転関節型・Drive制限・共通範囲の静的監査：成功。
- Unity batchmode：`No valid Unity Editor license found`、Unityログの終了コード198でテスト開始前に終了。起動元プロセスの終了コードではなくUnityログで判定。
- Editorの12チェックは作成・コンパイル済み、未実行。Play、mocopi実入力、実機への送信・駆動は未実施。

再実行はプロジェクトルートで `./Tools/Validate-ArmMapping.ps1`。これはコンパイル・数式検算・静的監査のみ。結果は `Logs/ArmMappingStaticValidation.txt`。

ライセンスが使用可能なUnity Editorで `Tools > Robot Arm > Validate A Mapping` を実行すると、Editモードの一時オブジェクトで12チェックを行う。PlayやUDP送信は行わない。結果は `Logs/ArmMappingValidation.txt`。最後の2項目は既知の欠点を再現する特性テストであり、PASSでもA全体の妥当性が確定したことにはならない。

**次に行うmocopi入力の確認**

最初はUDP Senderコンポーネントを無効にし、Unity内で実施する。今回シーンの送信設定は変更していない。

| 動作 | 観察 | 判定の考え方 |
|---|---|---|
| 基準姿勢で校正 | 全delta、最終指令 | 差分ゼロ、制限内の基準角 |
| 上腕を左右へ動かす | J1と他軸 | 操作意図の方向へ動くか、連動量 |
| 上腕を上下へ動かす | J2と他軸 | 特徴の変化と末端位置変化を分離 |
| 上腕固定で肘を曲げる | J3/J4 | 大きなJ4混入があれば独立操作として不適切 |
| 手首固定で前腕を傾ける | J5/J6 | 前腕姿勢の混入を計測 |
| 手首だけ曲げる／ひねる | J5/J6 | 回転方向・相互干渉・入力の観測可能性 |
| 腕の相対姿勢を保って胴体回転 | 全軸 | 身体基準かworld基準かの要求に照らして判断 |
| 姿勢反復・再装着 | 校正後の値・揺れ | 許容誤差は比較課題から事前に決める |

J3を3次元曲げ角、J4を別の相対回転、J5/J6を前腕に対する手の回転へ変更する案は、操作の意味を変更する。独立した6軸入力がmocopiで取得できるかも確認し、元Aと改訂Aを区別して記録する。

**Aの確定条件**

入力・座標系・操作意図を確定し、J4の干渉とJ5/J6の混入を解消するか、使用範囲を限定する。基準角・倍率・反転・制限値の決定手順を記録し、再校正で再現できることを確認する。その後、同じ作業領域と制限でBとの比較へ進む。
