# ロボットアーム遠隔操作：関連研究・現状比較・研究計画

調査日：2026-09-23。対象実装：RobotArm-joint、コミット `54812c4`。

**結論**

現在の mocopi → Humanoid → J1〜J6 の実装を比較基準として保存し、体幹相対座標に基づく直接マッピングと、手先位置を目標とする逆運動学（IK）を同じ入力・同じ課題で比較することを提案する。最初は手先の位置を操作し、姿勢は固定する。位置操作が成立した後に姿勢制御を追加する。

研究課題の候補は「少数の慣性センサによる骨格推定を用いた6軸アーム遠隔操作において、身体形状とロボット構造の違いを考慮したマッピングは、操作精度・習熟・負担をどう変えるか」。これは本調査からの提案であり、新規性や改善効果が確定したものではない。

コードから推定される注意点を以下に記す。いずれも今回の実測で発生を確認した故障ではない。

- 方向ベクトルは2点の差なので全身の平行移動には基本的に不変だが、体幹の回転には不変ではない。「world座標だから位置移動が直接すべて混入する」という説明は正確ではない。
- `rawElbow - baseElbow` は単純差分であり、符号付き角の境界で飛びが生じ得る。投影面が不適切な姿勢についても検証が必要。
- 手のEuler角は分解順序や特異姿勢に依存する。Quaternionへ変えるだけで入力精度が良くなるわけではなく、座標系と基準姿勢の対応も必要。
- `SetJointTarget()` でDrive限界に追加Clampしても、`GetRobotJoints()` はその前段の平滑化角を返す。制限値が違うと、Unityへの最終目標とUDP角度が食い違い得る。
- 送信側は `IsCalibrated` を使っておらず、シーンの `sendOnceOnEnable` も有効。校正前に角度が送られる構成になっている。
- mocopi Receiverにも受信時刻・バッファ処理がある。20 Hzは送信頻度であり、全体の遅延が50 msという意味ではない。
- Receiver、角度計算、送信がUpdateに関係するため、入力反映→角度計算→送信の実行順序を測定時に固定する。

**位置IKの具体案**

人の手位置を単にロボットへコピーするのではなく、体幹に対する手の位置を使う。

```text
p_rel(t) = R_torso(t)^T × (p_hand(t) − p_shoulder(t))
p_target(t) = p_robot_start + C × S × (p_rel(t) − p_rel(start))
```

`C` は人側基準からロボット基準への座標変換、`S` は動作範囲を合わせるスケール。Unityとロボットの座標系の手性・軸方向・単位を確認し、姿勢変換では基底変換も適切に扱う。体幹相対化は「胴体を回しても腕の相対姿勢が同じなら指令を保つ」という操作設計であり、全身移動でロボットを操作したい場合には別モードを設ける。

最初は位置だけを操作入力にし、手先姿勢は設定値を維持するIKとする。必要に応じて姿勢拘束を緩め、位置到達性との関係を測る。到達不能目標を無理に追わせず、最後の有効目標を保持するなど挙動を決める。

次に、位置・姿勢誤差と前回解からの変化量を用いる制約付き最適化へ拡張する。

```text
min_q  w_p ||p(q) − p_target||²
     + w_R ||Log(R_target^T R(q))||²
     + w_s ||q − q_previous||²
subject to 関節角・速度制限、および必要な衝突制約
```

これは提案する目的関数の概形。メートルとラジアンの尺度差を考慮して重みを定める。局所IKの収束や衝突回避を、この式だけで保証したことにはならない。

6軸で任意の手先位置3＋姿勢3を拘束すると、一般には肘位置を独立に合わせる余剰自由度はない。R1のような7自由度アームの肘姿勢最適化を追加するなら、姿勢拘束を緩める等の優先順位が必要。人間の肘姿勢と手先姿勢の完全一致を同時に要求しない。

**比較実験案**

主比較は A＝現行方式、B＝座標系等を整備した直接マッピング、C＝位置IK とする。最初から全変更をCだけに加えると改善要因が分からないため、通信周期・最終制限・フィルタ条件は可能な限り揃える。平滑化の比較は別の実験として切り分ける。

| 課題 | 主な評価指標 | 意図 |
|---|---|---|
| 基準姿勢で静止、腕方向を固定した体幹回転 | 出力角／手先の揺れ、意図しない変位 | 座標系とドリフトの影響 |
| 複数位置への到達 | 成功率、完了時間、目標との手先誤差 | 直接マッピングと位置IKの比較 |
| 直線・円軌道の追従 | 軌道RMSE、位相遅れ、角速度・加速度 | 精度と滑らかさの両立 |
| 手先姿勢の変更 | 姿勢角誤差、位置のずれ | P3で追加する姿勢制御の評価 |
| 小物の移載 | 成功率、落下・再試行、操作時間 | グリッパー導入後の実用課題 |
| 模擬的な入力停止・通信遅延 | 異常検出時間、停止までの時間、残留指令 | 動作条件の検証。初めはシミュレーションで実施 |

- 指令角とUnity目標角の一致は、実機の精度を示さない。実機関節読値による順運動学にもモデル誤差があるため、必要なら外部カメラ等で手先位置を測る。
- ソフトウェア内遅延と人の動作から実機応答までの全体遅延を区別する。PC間の片道遅延は時計同期なしでは正しく測れない。
- 同じ記録入力を用いる試験は再現性を確保できるが、操作しやすさを評価できない。後者には操作者を含む実験が必要。
- 予備実験は少人数で不具合と指標の妥当性を調べる。本実験の人数は予備実験の分散・効果量と研究目的から決める。
- 被験者内比較を基本候補とし、方式の順序を入れ替え、練習時間を揃える。成功率・時間に加え、負担や疲労の質問を記録する。少人数の結果を一般化しない。
- 合格する誤差や速度は、課題サイズ、実機精度、作業環境から設定する。先行研究の数値をそのまま合格基準にしない。

上表の適用判断は本プロジェクト向けの推論・提案であり、各論文がmyCobot 320で比較検証した結果ではない。

**研究としての主張の置き方**

「mocopiでロボットを動かした」だけでなく、構造の違う6軸アームに対して、どのマッピングがどの課題で有効かを示す研究にする。軸対応の調整、フィルタ改善、IK追加を別々に評価すれば、改善の理由を説明しやすい。

推奨する最初のテーマは「mocopi骨格入力によるmyCobot遠隔操作の関節マッピングと手先IKの比較」。身体の回転、異なる操作者、練習による変化を加えると、単なるデモを超えた評価にできる。発表上の新規性は、この調査を起点に追加の文献・引用追跡で確認する。
