# 指定した3姿勢への対応（最新仕様）

上={0,0,0,90,90,0}、前={0,-90,0,90,90,0}、右横={-90,-90,0,90,90,0}（J1〜J6、度）。ユーザーの訂正に従い、前・右横のJ2を-90度に変更した。

ロボット側の軸別到達限界を探す以前の方式を置き換えた。実際のArticulationアンカーと工具点から順運動学で3つの位置・向きを計算し、人の上・前・右横の登録位置と対応させる。範囲ではなく3つの対応点であり、最大可動域の測定ではない。

位置は3点の平面内をアフィン変換する。平面外は人とロボットの辺長比の平均で換算する設計とした。3点だけでは全3次元空間の変換は一意に決まらないため、この平面外の換算は仮定である。ほぼ一直線の登録や関節制限外の指定はエラーにする。

向き追従ONではロボット3姿勢の向きを補間し、登録した人の手の向きとの差分を重ねる。登録時と同じ手の位置・向きなら、対応するロボット基準の手先位置・向きが目標になる。向き追従OFFでは工具姿勢固定なので、指定した3姿勢の向きまで一致することは要求しない。

途中の目標はIKで解く。現在の解から収束しなければ指定3姿勢を初期解として再試行する。手先の位置・向きを制御するため、IKの別解によって関節角が指定と異なる場合はある。解が得られなければ直前の指令を維持する。衝突回避は含まない。

neutralは範囲登録後に設定でき、5cm・10度へ戻す必要はない。ただし3点の絶対対応を保つため、neutral設定で対応点をずらさない。開始時は現在の手に対応する目標位置へ、既存の関節速度制限付きで移動する。初回はマッピング先が到達可能かUnityで確認する。

範囲登録の手順はBegin→UP→FRONT→RIGHT→現在姿勢をneutralとして開始。画面に3組の関節角を表示する。人・ロボットのmin/max表示は対応点の外接範囲であり、到達可能な直方体を表すものではない。

登録点の一致と中点補間のEditorテストをValidate Workspace Mappingへ追加。実行環境のhelper_unknown_errorによりコンパイル・Editorテスト・Play確認は未実施。
